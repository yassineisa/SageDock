# Coding agent onboarding

Everything an AI coding agent (or a new human contributor) should read before changing
SageDock, gathered in one place so none of it has to be hunted for.

**Start with [REPO_CONTEXT.md](REPO_CONTEXT.md).** It is the detailed repository guide:
architecture, dependencies, core logic, invariants, the validation gate, and the mistakes
this codebase has already made once.

These are **handoff records, not specifications**. Each was accurate when written and says
which version it was written at. Where one contradicts the code, the code is right — but
read the document anyway, because it usually explains why the code is the way it is.

## What is deliberately not here

- [`../docs/DESIGN.md`](../docs/DESIGN.md) and
  [`../docs/BACKUP-FORMAT.md`](../docs/BACKUP-FORMAT.md) are **current, binding
  specifications** rather than handoff history, so they stay in `docs/`. Any UI change must
  comply with DESIGN.md.
- [`../docs/reviewer/`](../docs/reviewer/README.md) is written for a human reviewer
  assessing SageDock for university lab deployment. It is excellent orientation material and
  REPO_CONTEXT.md links into it throughout, but its audience is different.
- `../docs/qa/*.png` are tracked screenshot evidence, regenerated by the UI suite.

## The one thing to understand before changing anything

SageDock installs and owns a WSL 2 Linux distribution containing SageMath, while the
student's notebooks live in ordinary Windows folders **outside** it. The runtime is
disposable; the notebooks are not. Repair, reinstall and uninstall may destroy the former
and must never touch the latter. Most of the architecture follows from that one rule.
